# Harness engineering for Bacchus

Research checked November 18, 2026.

Bacchus should give the model responsibility for creative decisions within a production stage. For planning, that includes where a scene begins, what it should communicate, which available assets and motions serve it, and where new artwork is needed. The application owns stage transitions, project state, approvals, and execution. This gives the model room to solve a creative problem while making the consequences of a decision inspectable and controllable. Anthropic's workflow guide describes this division as predefined orchestration around model calls. Thoughtworks' November Radar identifies the harness around a model as a maintained, versioned engineering asset. [Building effective AI agents](https://www.anthropic.com/research/building-effective-agents) · [Technology Radar, vol. 35](https://www.thoughtworks.com/content/dam/thoughtworks/documents/radar/2026/11/tr_technology_radar_vol_35_en.pdf)

## Design the handoff before adding autonomy

**Make plans executable as data.** Give the planner the production brief, a read-only script with stable cue IDs, and a compact catalog of verified assets and engine capabilities. Return scene ranges, asset and action IDs, and explicit requests for missing art or unsupported motion. The application checks cue coverage and references, and can assemble one request from the missing-art items. The plan remains editable before approval. Schema-constrained decoding helps with shape, and local validation still needs to check project-specific facts. Provider refusals and truncated responses are distinct outcomes even when schema mode is enabled. [12-Factor Agents, control flow](https://github.com/humanlayer/12-factor-agents/blob/main/content/factor-08-own-your-control-flow.md) · [Claude structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)

**Record exact inputs and keep revisions addressable.** Record the project revision, source hash, method and schema version, asset catalog revision, provider model, run status, and output revision. Store provider usage where available. Use the recorded output for replay and visual review. Running a pinned model again can yield a different proposal, so a rerun creates a new candidate. Keep the model adapter and renderer behind stable interfaces so either can change independently. [Scaling Managed Agents](https://www.anthropic.com/research/managed-agents) · [Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

**Bind review decisions to a specific result.** Approve a particular candidate and recheck that identity at render start. A change to the input, scene plan, or relevant assets makes the old approval stale for the new candidate. Show changed scenes, stills or a scrubber, and validation findings together so the reviewer can see what the decision covers. Keep pause, retry, and render as explicit commands. Research on stale authorization studies this problem at the commit boundary, and Temporal describes durable handoffs between adaptive model work and approvals. [Temporary authority, permanent effects](https://arxiv.org/abs/2607.10487) · [Who needs workflows when you have agents?](https://temporal.io/blog/who-needs-workflows-when-you-have-agents)

**Treat interruption and cost as application concerns.** Record an attempt before a paid call. On restart, expose incomplete attempts and preserve previously approved artifacts. Use idempotency keys or provider status when the API offers them. A timeout on a paid operation with an unknown result calls for reconciliation before retry. Apply a request timeout and output token limit, and budget each follow-up call against the remaining allowance. A local transactional store is enough to explore this for a single-user prototype. [Where Does Exactly-Once Live?](https://arxiv.org/abs/2609.29095) · [Atomic commit in SQLite](https://www.sqlite.org/atomiccommit.html)

**Check observable output.** Use code for invariants such as cue coverage, valid motion parameters, media presence, frame dimensions, and duration. When a model reviews editorial quality, use a fresh call that sees the candidate stills or clips and a short rubric. Ask for a scene ID, timestamp, evidence, and severity, and allow it to say the supplied evidence is insufficient. Human review still authorizes the result. Anthropic found that a separate evaluator needed calibration against human judgment even in a harness built specifically for design and software QA. [Harness design for long-running applications](https://www.anthropic.com/research/harness-design-long-running-apps) · [Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

## Exercise the boundary on one film

Start with one film excerpt and one style. Run a fixture and a live model through the same planner contract, then follow the plan through edits, validation, missing-art handling, and visual review. Compare the resulting candidate with the finished reference. The useful question is whether the scene vocabulary preserves the editorial ideas and whether the reviewer can make corrections quickly.

Turn observed failure modes into fixtures. Useful cases include an unassigned narration cue, invented asset ID, unsupported motion, omitted explicit music decision, stale approval after an edit, and an interrupted model request. Keep deterministic cases in the ordinary test suite. For creative quality, use a few representative reference scenes and examples of what succeeds or fails. When changing a prompt, model, schema, or vocabulary, compare multiple runs for coverage, reference validity, manual correction time, and cost. Keep extra planning or critique rounds only where the comparison shows they help. [Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) · [Harness design for long-running applications](https://www.anthropic.com/research/harness-design-long-running-apps)

The cited case studies concern software development and general workflow execution. The Bacchus choices above are applications of those findings. The one-film test is how to learn which controls and creative vocabulary work for animation.
